Mentis 系统架构与运行机制讲解报告

Training-free Mental World Model Baseline for Multiple-choice Situated Reasoning

系统定位: Mental World Model 方法类型: Training-free API-based baseline 核心机制: Counterfactual state transition 输出契约: generated_results JSON

摘要

Mentis 是一个面向多选情境推理任务的 training-free Mental World Model 基线系统。它的核心目标不是让大模型直接读取题目与选项后选择答案，而是强制模型显式执行一条世界建模链路: 从场景解析当前世界状态 s_t，从目标人物视角生成局部观察 o_t，将每个候选动作拆成物理与心理动作成分，再对每个动作分支并行模拟下一时刻状态 s_{t+1}，最后基于模拟出的未来状态进行价值评估并确定 final_action。

一句话概括: Mentis 将多选题求解转化为显式的“状态表示 -> 视角观察 -> 动作分解 -> 反事实状态转移 -> 价值评分 -> 确定性决策”过程，从而把答案建立在可检查的物理与心理状态演化上。

1. 输入与输出数据样式

1.1 输入样本的逻辑结构

Mentis 直接消费验证集 JSON/JSONL 样本。每条样本包含场景、目标人物、问题、候选动作，以及用于离线评估的 golden annotation。主 pipeline 在常规实验中不会读取 golden answer，除非显式打开 oracle ablation。 

{
  "sample_id": 1,
  "domain": "dormitory",
  "domain_category": "residential",
  "scene": "social_cooperation",
  "num_of_characters": 2,
  "story": {
    "text": "Amy ... must decide what to do next.",
    "images": ["optional/image/path.jpg"]
  },
  "target_agent": "Amy",
  "question": "Amy wants to finish her watercolor tonight ... What should Amy do next?",
  "options": [
    {
      "option_id": "A",
      "action_description": "Amy places the water bottle ... asks Lisa to move the bag ..."
    },
    {
      "option_id": "B",
      "action_description": "Amy yanks Lisa's sports bag off the chair ..."
    }
  ],
  "golden_answer": {
    "current_state_s_t": {},
    "target_agent_observation_o_t": {},
    "next_state_s_{t+1}": {},
    "score": {},
    "final_action": "A"
  }
}
字段 作用 是否进入主推理链路
story.text, story.images 原始场景输入，可以是文本、图像或二者组合。 是，作为 State Parser 的场景信息。
target_agent 数据集给出的目标人物描述，例如 “Amy”。 是，运行时直接以 target_agent 传递。
question 目标人物需要完成的任务、意图或约束。 是，在 scoring 阶段使用。
options 候选动作集合，通常为 A 到 F 六个动作。 是，进入 Target Pseudo Agent 和 Action Parser。
golden_answer 评估标签，包含标准状态、观察、未来状态、分数和答案。 常规主实验不使用，仅评估或 oracle ablation 使用。

1.2 输出样本的逻辑结构

Mentis 不覆盖原始输入样本，而是在每条样本后追加 generated_results。这样可以同时保留原题、模型中间状态、最终选择和调试信息。 

{
  "sample_id": "1",
  "generated_results": {
    "status": "success",
    "current_state_s_t": {
      "physical_state": {},
      "mental_state": {}
    },
    "target_agent_observation_o_t": {
      "physical_observation": {},
      "mental_observation": {}
    },
    "sampled_actions": [
      {
        "option_id": "A",
        "action_description": "...",
        "source": "test_options"
      }
    ],
    "candidate_actions": [
      {
        "option_id": "A",
        "raw_action_description": "...",
        "physical_action_description": "...",
        "mental_action_description": "..."
      }
    ],
    "next_state_s_{t+1}": {
      "A": {
        "physical_state": {},
        "mental_state": {}
      }
    },
    "score": {
      "A": {
        "mentally_consistent": "1",
        "physically_plausible": "1",
        "socially_appropriate": "1",
        "safety_legality_veto": "false",
        "raw_value_score": "1",
        "overall_score": "1",
        "reasoning": "concise rationale"
      }
    },
    "final_action": "A",
    "decision_trace": {},
    "metadata": {}
  }
}
输出设计的学术意义: Mentis 输出不仅给答案，还保留 s_t、o_t、每个候选动作的 s_{t+1} 和评分理由。因此可以分析模型到底错在状态理解、视角限制、物理转移、心理转移、价值判断，还是最终决策规则。

2. 系统运行总览

当前 full MWM pipeline 可以表示为以下线性流程。图中每个方块对应当前实现中的一个模块或一个确定性处理步骤。

图 1. Mentis full MWM pipeline 概览。
scene -> s_t
s_t + target_agent -> o_t
options -> sampled_actions
sampled_actions -> candidate_actions
for each action branch:
  physical_transition: s_t + a_t^phy -> s_{t+1}^phy
  mental_transition:   s_t + a_t^phy + a_t^ment -> s_{t+1}^ment
  merge -> s_{t+1}
(s_t, o_t, action, s_{t+1}, question) -> score
score table -> deterministic decision -> final_action

3. 核心表示设计

3.1 WorldState: 联合物理与心理状态

Mentis 将当前世界状态统一表示为 JSON 文本状态 WorldState。它包含两个顶层字段: physical_state 和 mental_state。

Physical State

描述物体、人物、空间关系、接触关系和环境条件。

{
  "entity_and_attribute": {
    "objects": [
      {
        "intrinsic_property": {"appearance": null},
        "contextual_attributes": {
          "position": null,
          "physical_condition": null,
          "semantic_content": null
        }
      }
    ],
    "characters": [
      {
        "intrinsic_property": {"appearance": null},
        "contextual_attributes": {
          "facial_expression": null,
          "gaze": null,
          "body_motion": null,
          "position": null,
          "semantic_content": null
        }
      }
    ]
  },
  "relations": {
    "spatial_relations": {
      "relative_position": [null],
      "distance": [null],
      "occlusion": [null]
    },
    "contact_relations": [null]
  },
  "environment": {}
}

Mental State

描述人物的信念、注意、目标、意图、情绪、偏好、规范、态度和关系。

{
  "mental_entity_and_attribute": {
    "individual": [
      {
        "identity_attributes": {
          "name": null,
          "occupation": null
        },
        "epistemic_state": {
          "beliefs": [null],
          "attention_focus": null
        },
        "motivational_state": {
          "goals": [null],
          "intentions": [null]
        },
        "affective_state": {"emotions": [null]},
        "normative_state": {
          "rules": [null],
          "customs": [null]
        }
      }
    ]
  },
  "relations": {
    "attitudes": {},
    "role_relations": {}
  },
  "atmosphere_of_environment": null
}

3.2 Target Observation: 局部第一人称观察

o_t 使用与 WorldState 相似的 schema，但语义上不是全局状态。它表示 target agent 在当前时刻能够看到、听到、触摸到、定位到，或基于可观察线索合理推断出的信息。

视角约束: Observation Generator 必须避免“读心式泄漏”。例如，全局 mental_state 中可能包含 Lisa 的真实想法，但 Amy 的 o_t 只能包含 Amy 根据 Lisa 的表情、语言、动作和上下文推断出的 Lisa 心理状态。

3.3 CandidateAction: 动作的双通道表示

每个候选动作被拆成物理动作成分和心理/语义动作成分。这一设计让后续 transition 可以分别追踪“动作如何改变物理世界”和“动作如何改变心理世界”。 

{
  "option_id": "A",
  "raw_action_description": "Amy says ... and asks Lisa to move the bag.",
  "physical_action_description": "Amy speaks, puts the bottle and towel down, waits near the door",
  "mental_action_description": "Amy politely corrects Lisa's belief and requests help without blame"
}
动作维度 含义 例子
a_t^phy 身体动作、语音载体、手势、物体操作、直接物理影响。 说话、挥手、拿起物体、放下毛巾、指向门口。
a_t^ment 动作承载的意图、情绪、社交意义、认知控制或信念更新目标。 安慰、请求、欺骗、纠正误解、表达友好、威胁。

4. 运行时字段标准化

4.1 为什么运行时直接使用 target_agent

这不是改变数据语义，而是在运行时添加一个更明确的别名。原始数据字段 target_agent 通常是自然语言描述，例如 “Amy” 或 “the boy holding the box”。进入 WorldState 后，系统还可能解析出结构化的角色 ID 或角色条目。为了避免“数据集里的目标人物描述”和“状态 schema 中的角色标识”混淆，pipeline 使用: 

data["target_agent"]

后续模块统一使用 target_agent 来表达“题目指定的目标人物自然语言描述”。它会进入 Observation Generator 和 Scoring Module。

4.2 为什么把 story.text/images 整理成 _media_scene

_media_scene 是运行时内部字段，用于统一文本、图像、视频输入形态，并解析媒体路径。它不是输出契约的一部分。 

{
  "_media_scene": {
    "text": "scene text ...",
    "image_paths": ["resolved/path/to/image.jpg"],
    "video_path": "",
    "modality": "text" | "images" | "video"
  }
}

这样 State Parser 和 LLM client 可以用统一格式接收多模态场景，而不需要在每个模块里分别处理 story.text、story.images 或未来可能出现的 video 字段。

5. Pipeline 分步详解

0

输入标准化

系统首先调用 normalize_record 和 SampleInput.as_runtime_dict()，将输入样本整理成 pipeline 内部格式。该步骤不调用 LLM。

处理 目的
sample_id 转为字符串 保证 batch 输出、日志文件和评估索引稳定。
保留 target_agent 把输入样本中的目标人物字段直接传给后续模块。
story 整理为 _media_scene 统一 text/image/video 输入，并解析相对媒体路径。
保留 golden_answer 但主链路不使用 防止答案泄漏，同时支持后续评估。
1

State Parser: 从场景到 s_t

State Parser 负责将当前场景解析为联合世界状态 s_t。它是整个系统的基础，因为后续观察生成、状态转移和评分都依赖这个结构化状态。

输入 去掉 golden_answer 的样本内容，以及 _media_scene 媒体上下文。
模型 parser_model，当前默认配置为 gpt-5.5。
输出 WorldState: {"physical_state": ..., "mental_state": ...}。
验证 输出必须通过 WorldState schema 和模板归一化。
State Parser prompt 结构 
Task: Parse multimodal scene into joint physical-mental WorldState
Return only valid JSON. Do not use markdown. Keep reasoning concise.

You must parse the scene at the current moment into s_t.
Replace null placeholders with observed or reasonably inferred content.
If a field cannot be determined from text/images/video, keep that field as null.
Preserve every key in the template and do not add extra keys.

Use the exact top-level keys physical_state and mental_state.
Physical state must describe objects, characters, spatial/contact relations, and environment.
Mental state must describe each character's beliefs, attention, goals, intentions,
emotions, preferences, norms, attitudes, role relations, and atmosphere.

Strict local state template:
{WORLD_STATE_TEMPLATE}

Input sample without golden answer:
{sample}

这一 prompt 的关键约束是: 不让模型自由写 narrative，而是强制填充严格模板。这样生成的 s_t 能够被后续模块机械地消费和评估。

2

Observation Generator: 从全局状态到目标人物观察 o_t

Observation Generator 将全局 s_t 渲染成 target agent 的局部第一人称观察 o_t。这一步体现 Mentis 的 POMDP 式视角限制。

输入 world_state 和 target_agent。
模型 world_model，当前默认配置为 gpt-5.5。
输出 TargetObservation: {"physical_observation": ..., "mental_observation": ...}。
核心风险 不能把全局隐藏心理状态直接复制给 target agent。
Observation Generator prompt 结构 
Task: Render first-person target observation from global WorldState
Return only valid JSON. Do not use markdown. Keep reasoning concise.

Input is the current strict WorldState s_t and the dataset's target agent description.
Return the target agent's observation o_t from that agent's perspective.

physical_observation must include only facts the target can see, hear, touch, locate,
or otherwise directly perceive at the current moment.
Hidden, occluded, or unknown physical facts must be null.

mental_observation includes the target agent's own beliefs, goals, intentions,
emotions, preferences, and norms, plus only cue-supported inferences about other agents.
Do not copy hidden global mental state as mind reading.

Preserve every key in the template. Do not add extra keys.
Use only the top-level keys physical_observation and mental_observation.

Strict local observation template:
{TARGET_OBSERVATION_TEMPLATE}

Dataset target agent description:
{target_agent}

Current WorldState s_t:
{world_state}
3

Target Pseudo Agent: 把选项转成候选动作

Target Pseudo Agent 不调用 LLM，也不生成新的动作。它把数据集中的每个 option 当作 target agent 的一个候选动作分支，转为 SampledAction。 

OptionInput:
{
  "option_id": "A",
  "action_description": "Amy places the water bottle ..."
}

SampledAction:
{
  "option_id": "A",
  "action_description": "Amy places the water bottle ...",
  "source": "test_options"
}

如果候选项数量不是 6，系统不会中断，而是在 metadata 中记录 warning。这保证系统可以支持任意 K 个选项。

4

Action Parser: 将动作拆成物理与心理成分

Action Parser 对每个 SampledAction 单独调用一次 LLM，并且这些调用并行执行。它只看当前动作文本，不看 target agent、question、observation 或 state。

设计理由: 这一步必须保持 action-only。如果 parser 看到了 question 或当前状态，它可能会为了“迎合正确答案”而改写、补全或重排动作，破坏候选动作本身的可比性。
Action Parser prompt 结构 
Task: Parse one candidate action into physical and mental dimensions
Return only valid JSON. Do not use markdown. Keep reasoning concise.

Input is exactly one natural-language candidate action a_t.
Use only this action text.
Do not use target-agent identity, question text, observation, current state, or option correctness.
Do not add, drop, merge, rank, or rewrite actions.

a_t^phy is the physical execution, physical carrier, or direct physical-world effect.
It includes bodily movement, object manipulation, speech as sound production,
gaze, facial expression, gesture, touching, moving, handing an object, pointing, etc.

a_t^ment is the semantic, intention, emotion, cognitive-control, or social component.
It includes comforting, requesting, threatening, deceiving, persuading, reassuring,
misleading, expressing friendliness, refusing, or updating someone's belief or goal.

If a dimension is not explicitly present, return an empty string.

Output schema:
{
  "a_t^phy": "physical execution/carrier/direct physical effect, or empty string",
  "a_t^ment": "semantic, intention, emotion, cognitive, or social component, or empty string"
}

Action a_t:
{action_description}
动作文本 a_t^phy a_t^ment
waves waves hand 空字符串，除非文本说明是在 greeting/warning。
says "Don't worry" speaks the sentence reassures the listener
points to the exit and tells him to leave points to the exit and speaks directs him to leave
5

State Transition: 对每个候选动作模拟未来状态

对于每个候选动作，Mentis 都运行一个独立 branch。branch 内部并行调用 Physical Transition 和 Mental Transition，分别预测 s^{phy}_{t+1} 与 s^{ment}_{t+1}，再由 NextStateMerger 合并为完整 s_{t+1}。

图 2. 单个候选动作分支内部的状态转移。

5.1 Physical Transition

Physical Transition 只更新物理状态，不更新心理状态。它需要判断动作载体是否可执行，以及动作会如何改变物体、人物、空间关系、接触关系和环境。

Physical Transition prompt 结构 
Task: Predict physical state transition for one candidate action
Return only valid JSON. Do not use markdown. Keep reasoning concise.

Compute s^{phy}_{t+1} from the physical action a^{phy}_t,
the current physical state s^{phy}_t, and the current mental state s^{ment}_t.
Use s^{ment}_t only as context for intention, attention, belief, or social constraints
that affect what physical action is attempted; do not update mental_state here.

Transition procedure:
identify the physical carrier in physical_action_description,
check reachability, hand occupancy, affordance, visibility, occlusion,
collision, contact, containment, support, temporal order, and environmental constraints,
then update only objects, characters, relations, and environment facts that physically change.

If a^{phy}_t is empty, copy s^{phy}_t unless speech or gesture physically occurs.

Output exactly the strict physical_state schema.
Do not return physical_state, mental_state, or wrapper keys.

s^phy_t:
{physical_state}

s^ment_t:
{mental_state}

CandidateAction:
{action}

5.2 Mental Transition

Mental Transition 只更新心理状态。它从当前物理状态、当前心理状态、物理动作载体和心理动作语义出发，预测人物信念、目标、情绪、关系和社会态度如何变化。

Mental Transition prompt 结构 
Task: Predict mental state transition for one candidate action
Return only valid JSON. Do not use markdown. Keep reasoning concise.

Compute s^{ment}_{t+1} from the physical action a^{phy}_t,
the current physical state s^{phy}_t, the mental action a^{ment}_t,
and the current mental state s^{ment}_t.

This module runs in parallel with the physical transition submodule,
so do not rely on s^{phy}_{t+1}.

Update beliefs, attention, goals, intentions, emotions, preferences, norms,
attitudes, role relations, and atmosphere when they are caused by:
attempted physical carrier, explicit mental/social intent, speech content,
gesture, deception, reassurance, persuasion, threat, cooperation, or norm violation.

If a^{ment}_t is empty, still update mental_state only when the physical carrier
would be perceived and naturally change beliefs or emotions.
Otherwise preserve s^{ment}_t.

Output exactly the strict mental_state schema.
Do not return physical_state, mental_state, or wrapper keys.

s^phy_t:
{physical_state}

s^ment_t:
{mental_state}

CandidateAction:
{action}

5.3 NextStateMerger

合并器不调用模型。full 模式下，它直接将 physical transition 输出的 PhysicalState 和 mental transition 输出的 MentalState 组成下一时刻 WorldState。 

s_{t+1} = {
  "physical_state": s^{phy}_{t+1},
  "mental_state": s^{ment}_{t+1}
}
6

Scoring Module: 对每个 imagined branch 评分

Scoring Module 的输入不是单纯的 question 和 options，而是完整反事实分支: 

(target_agent, question, s_t, o_t, a_t, s_{t+1})

它对每个 action branch 输出三个维度分数、一个安全/合法性 veto、本地价值分和最终排序分。

评分维度 判断问题
mentally_consistent 动作是否符合 target agent 在 o_t 下的目标、信念、意图、情绪和任务约束。
physically_plausible 动作和模拟出的 s_{t+1} 是否能从 s_t 物理上成立。
socially_appropriate 动作是否符合当前关系、角色、礼貌、规范、道德和社会场景。
safety_legality_veto 如果动作或结果严重不安全或违法，直接 veto。
Scoring prompt 结构 
Task: Evaluate one imagined action branch
Return only valid JSON. Do not use markdown. Keep reasoning concise.

Use the full tuple:
(target_agent_description, question, s_t, o_t, a_t, s_t+1)
to score this single action branch.
Do not choose the final answer and do not add extra keys.

mentally_consistent evaluates whether the action satisfies the current target agent's goal
and matches the target agent's mindset/personality under o_t.

physically_plausible evaluates whether the action and imagined s_t+1
are physically possible from s_t.

socially_appropriate evaluates custom, moral, politeness, role,
and social norm appropriateness.

safety_legality_veto must be true if the action or resulting state is illegal
or seriously unsafe; otherwise false.

Output schema:
{
  "mentally_consistent": "0.0",
  "physically_plausible": "0.0",
  "socially_appropriate": "0.0",
  "safety_legality_veto": "true/false",
  "reasoning": "concise rationale"
}

target_agent_description:
{target_agent}

question:
{question}

s_t:
{world_state}

o_t:
{observation}

a_t:
{action}

s_t+1:
{next_state}
7

Decision Module: 从分数到 final_action

Decision Module 不调用 LLM。它基于 Scoring Module 的结果进行确定性排序。当前默认权重为:

raw_value_score = 0.45 * mentally_consistent + 0.35 * physically_plausible + 0.20 * socially_appropriate

如果 safety_legality_veto = true，则 overall_score = 0.0。否则 overall_score 使用上面的加权分数。LLM 只输出维度分数、veto 和 reasoning；当前实现会在本地计算并写入 raw_value_score 与 overall_score。

排序优先级 含义
1. overall_score 总分最高者优先。
2. physical_plausible 若总分相同，更物理可行的选项优先。
3. mentally_consistent 若仍相同，更符合目标人物心理目标的选项优先。
4. socially_appropriate 若仍相同，更符合社会规范的选项优先。
5. option_order 若完全并列，A/B/C 等顺序靠前者优先。
8

输出组装与日志

最后，pipeline 将所有中间结果组装到 GeneratedResults 中，包括当前状态、观察、采样动作、动作分解、每个选项的下一状态、评分表、最终动作、决策 trace 和 metadata。

如果某个样本运行失败，系统不会中断整个 batch，而是写出: 

{
  "generated_results": {
    "status": "failed",
    "error_type": "...",
    "error_message": "..."
  }
}

当前配置默认保存 prompt 和 raw LLM output 到 outputs/logs，便于复现实验和错误分析。

6. Prompt 设计总表

Mentis 的 prompt 设计遵循三条原则: 第一，所有模块返回 JSON；第二，每个模块只完成自己的局部任务；第三，评分必须基于显式状态转移，而不是直接猜答案。

模块 Prompt 任务 输入 输出 schema 关键防护
State Parser Parse multimodal scene into joint physical-mental WorldState 样本场景和媒体上下文 WorldState 去掉 golden answer，严格模板，不写 markdown。
Observation Generator Render first-person target observation s_t, target agent description TargetObservation 避免 hidden global mental state 泄漏。
Action Parser Parse one candidate action 单条 action text {"a_t^phy": ..., "a_t^ment": ...} 不看题目、不看状态、不改写动作。
Physical Transition Predict physical state transition s_t, action PhysicalState 只更新物理状态，不更新 mental state。
Mental Transition Predict mental state transition s_t, action MentalState 不依赖 s^{phy}_{t+1}，因为二者并行。
Scoring Module Evaluate one imagined action branch s_t, o_t, action, s_{t+1}, question ScoreResult 不直接选择 final answer，只给单分支分数。
重要边界: 当前实现将 Value Evaluator 拆成 Scoring Module 和 Decision Module。Scoring Module 是 LLM prompt，Decision Module 是确定性规则。因此最终答案不是模型在 scoring prompt 里直接选择的，而是分数表经过固定规则计算出来的。

7. 日志、评估与消融实验

7.1 默认配置

配置项 当前默认值 说明
models.parser_model gpt-5.5 用于 State Parser 和 Action Parser。
models.world_model gpt-5.5 用于 Observation Generator、Physical Transition、Mental Transition。
models.scoring_model gpt-5.5 用于 Scoring Module。
transition.max_concurrency 6 候选动作 branch 的最大并发数。
scoring.weights 0.45 / 0.35 / 0.20 心理目标一致性、物理可行性、社会规范适当性。
--ablation oracle_state / oracle_observation 显式启用时 只有 oracle ablation 会读取对应 gold state 或 gold observation。
logging.save_raw_llm_outputs true 保存原始模型输出，便于审查与复现。

7.2 可支持的消融实验

Mentis 的模块化设计天然支持消融。当前实现包含以下运行模式:

模式 含义 研究问题
full_mwm 完整 Mental World Model pipeline。 显式状态建模与反事实模拟的完整能力。
direct_answer_baseline 直接让模型根据 scene、question 和 options 选择答案。 显式 MWM 链路相对直接答题是否更可解释、更稳定。
no_mental_information 在 scoring/evaluation 输入中隐藏 mental state 和 mental observation。 心理信息对动作评分和最终选择有多重要。
no_physical_information 在 scoring/evaluation 输入中隐藏 physical state 和 physical observation。 物理约束与可观察事实对动作评分有多重要。
oracle_state 使用 golden_answer.current_state_s_t 作为当前状态。 隔离状态解析误差，观察后续模块在 gold state 条件下的表现。
oracle_observation 使用 golden_answer.target_agent_observation_o_t 作为 target observation。 隔离观察生成误差，评估动作分解、转移和评分模块的上限。

8. 总结

Mentis 的完整运行可以被理解为一种显式反事实模拟框架。对于每个候选动作，系统先构建当前世界状态和目标人物视角，再模拟该动作会造成的物理与心理后果，最后根据这些后果是否符合目标人物意图、物理约束和社会规范进行评分。它的主要优点是中间过程透明、输出可审查、模块可消融，并且能够将错误定位到具体推理阶段。

Input -> s_t -> o_t -> CandidateAction -> s_{t+1} branches -> scores -> final_action

因此，Mentis 不是一个“直接答题”系统，而是一个以 Mental World Model 为核心的结构化推理 baseline。
